* Git history as research history

This repository treats Git history as part of the scientific record.

The rewritten history is organized around validated model phases rather than
only software actions. Each commit message records:

- the model phase (V0.1 ... V0.6);
- the role of the change in the research workflow;
- whether it introduces physics, validation, study infrastructure, a correction,
  or a numerical result.

The file trees are not changed by the history rewrite. Only commit messages and
commit identities are regenerated.

** Reading the history

Recommended commands:

#+begin_src sh
git log --graph --decorate --oneline --all
git log --graph --decorate --format=medium --all
git show v0.5
#+end_src

The short graph gives the development structure.

The medium/full log gives the scientific commentary associated with every
commit.

** Policy for future versions

For each new model version:

1. branch from the last validated main;
2. add one identifiable physical mechanism;
3. preserve a limiting case that recovers the previous version;
4. add unit/regression tests;
5. run quick/preflight simulation;
6. run controlled sensitivity or convergence studies;
7. commit numerical evidence with a specific result description;
8. pass pytest, Ruff and mypy;
9. merge through a version PR;
10. create an annotated version tag only after validation.

Generic messages such as:

  Add PEMFC validation results

should no longer be used.

Prefer messages such as:

  [V0.6] Record nominal finite-transfer validation
  [V0.6] Verify k_a=0 continuity with V0.5
  [V0.6] Add anode-transfer sensitivity study

The Git history should make the physical reasoning legible without requiring
the reader to reconstruct it from file diffs alone.
